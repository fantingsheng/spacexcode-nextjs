这个月 AI 圈的消息密度有点高。把几条看起来不相干的新闻放在一起看，会发现它们讲的其实是同一件事：模型本身的“军备竞赛”还在继续，但真正的胜负手已经换到了别的地方。

## 一、开源模型的天花板，又被顶高了一次

10 月 24 日凌晨，月之暗面发布 Kimi K3.1 Pro：总参数 2.8 万亿，支持 100 万 token 上下文，继续蝉联全球参数规模最大的开源模型。

比参数更值得看的是榜单位置。在 Artificial Analysis 智能指数上它排到全球第 4、开源模型第一；在考察编程智能体的 Terminal-Bench 4.0 上拿到 65.7%，与 Claude Opus 5.5 的 66.4% 相差不到 1 个百分点，并且超过了 GPT-6 Astra 的 58.2%。3D 方向也有明显进步，BenchCAD 基准上借助工具拿到 92.7%。

一年前大家讨论的还是“开源模型落后闭源半年到一年”，现在在头部，这个差距已经要拿个位数百分点来衡量了。对应用方来说这意味着选择的余地变大：同一档能力，可以用闭源 API，也可以用可私有化部署的开放权重。

来源：[证券时报 / 每日经济新闻](https://stcn.com/article/detail/4270933.html)

## 二、算力自主：从“能推理”到“能训练”

10 月 22 日，科大讯飞在 1024 开发者节上发布星火 X2.6，293B-A30B 的端云一体架构，支持 1M 上下文窗口。

这条新闻里我认为最重要的一句是“基于全国产算力完成训练”。在国产芯片上跑推理，和在上面完整训出一个大模型，是难度完全不同的两件事——显存和带宽的限制会直接卡住长上下文训练。讯飞给出的解法是长程任务动态并行训练，把超长上下文训练效率提升约 4 倍；推理侧用自适应存算协同，效率提升约 4.5 倍。

另一个有意思的方向是端云一体：简单任务留在端侧，复杂任务上云，敏感信息先在本地脱敏。这其实是企业落地时最现实的诉求——不是模型不够强，而是数据不敢往外发。

## 三、真正的战场，已经转移到场景

如果说前两年比的是“谁的模型更聪明”，今年比的就是“谁能把模型塞进别人的工作流里”。这个月几个信号很一致：

- **金融**：Kimi 针对事实准确性做了专项优化，内部压力测试里单项事实陈述错误率从 23.4% 降到 8.3%
- **法律**：在贴近真实律所工作的 Harvey LAB 基准上，从上一代的 0 分提升到 26.7%，Harvey 随后基于它发布了法律行业专属模型
- **分发渠道**：Amazon Bedrock 以分成模式接入 Kimi K3，这是中国大模型公司第一次以这种模式进入全球云厂商的模型货架；企业用户也可以在 OpenAI 的 Codex 里直接调用，费用计入既有采购额度

模型能力正在被“打包进工作流”卖出去，而不是按 token 卖。这对做应用的人来说是好事：中间层的价值被压缩，应用层可以直接够到能力。

## 四、三个冷静的判断

热闹归热闹，几点冷思考还是要记下来：

**参数继续膨胀，但不再是差异化。** 开源模型已经到 2.8 万亿参数，可真正拉开差距的是后训练数据的质量和 RL 环境的丰富度，而不是纯参数量。

**长程 Agent 变强，但评测 ≠ 生产。** 发布会上的“端到端交付完整项目”很好听，可评测通过率不等于生产可用率，沙箱、回滚、Token 成本都是实打实的隐形成本。

**场景专用化，短期是护城河。** 金融、法律、3D 的专用模型密集出现，靠行业 know-how 变现没问题，但长期会被通用模型吃掉大半。

尤其第二点。一个 Agent 在基准上能跑通，和在真实环境里连续跑三天不出事，中间隔着的工程工作量常常被低估：

```ts
// 长程任务的循环本身很简单，难的是每一步失败之后怎么恢复
while (!done) {
  const plan = await model.plan(task, history);
  const result = await tools.run(plan.nextStep);

  history.push(result);
  done = result.ok && plan.isLastStep;
}
```

真实系统里，这段代码的每一行后面都要挂上重试、超时、幂等和人工兜底。模型越强，这些“无聊”的部分反而越决定项目能不能上线。

## 写在最后

这个月给我的整体感受是：技术曲线的斜率在放缓，但落地曲线的斜率在变陡。开源与闭源的差距、国产算力与海外算力的差距都在收窄，接下来的竞争会更多发生在数据、场景和工程细节上——而这些恰好是不太容易被一条发布会新闻讲清楚的部分。

对个人来说，比较务实的做法大概还是那两条：把模型当成一个能力很强但需要约束的同事，然后把省下来的时间花在理解业务上。
